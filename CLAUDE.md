# Hearth: notes for agents

Hearth is a one-person iPhone app (SwiftUI) plus a small relay on the owner's
iMac. The design is the "Hearth — communication hub" Design canvas; its screens
and copy are the source of truth for the UI. The plan of record is
`~/.claude/plans/typed-tinkering-garden.md` on the iMac; `docs/architecture.md`
summarizes it.

## Layout

- `Packages/HearthKit/`: shared, Foundation-only, builds on Linux. Domain model,
  agenda merge, mail rules, trust policies, relay DTOs, the Claude client.
  `HearthKitTestSupport` holds the fictional fixtures.
- `Relay/`: Vapor 4 + Fluent/SQLite. Targets: `RelayCore` (config, gmailkit
  bridge, store), `Jobs` (timed work, read-only Google), `Executor` (approved
  writes), `App` (routes, wiring), `Run`.
- `iOS/`: `project.yml` (XcodeGen; the .xcodeproj isn't committed), `HearthCore`
  (app logic, macOS-testable), `App` (SwiftUI), `Widgets` (StandBy widgets),
  `Share` (share extension), tests.
- `deploy/`: the relay's launchd kit. `docs/`: architecture, deploy, design map.

## Rules that matter

- **Ask before acting.** Nothing writes to mail or calendars without the owner's
  tap. Claude proposes; the phone sends approved actions to `POST /v1/actions`
  with an idempotency key. `Jobs` must never depend on `Executor`
  (`DependencyGraphTests` enforces it).
- **gmailkit tools are allowlisted** (`GmailkitTools`). Never add
  `gmail_delete_permanently`, `gmail_save_attachments`, or any `attachments` /
  `out_dir` argument. Trash is the strongest delete.
- **Surprise guard and busy-only.** The partner's events leave the relay
  busy-only; surprise plans go only to the owner's primary account, marked
  private, and widgets show them as "Private".
- **Public repo.** No real names, emails, church or job details, tokens or keys
  in code, fixtures, tests or commits. Fixtures use the fictional Rivera
  household (Sam and Robin, Maple Grove). Real household details live in
  `~/HearthRelay/household.json` on the iMac, never in git.
- **Claude API (2026-10-21):** no `temperature`/`top_p`/`top_k`, no forced
  `tool_choice`, no prefill; set `effort`; keep transcripts append-only; Opus
  requests send `fallbacks: "default"`, Haiku requests never do. See
  `ClaudeRequest`.

## Swift that works on Linux (the CI runs HearthKit and the relay there)

- No `async let` in HearthKit or the relay (it crashes on Swift 6.2 Linux).
- No `NSString` bridging (`as NSString`), `String(format:)`, or `NSLock.withLock`.
- Inject clocks (`HearthClock`, `ManualClock`); no sleep-based tests.
- Fluent query builders can't cross into an actor: build and run them in a
  `nonisolated` function.

## Tests and CI

- `make test` runs what CI runs. `make test-all` adds the simulator suites,
  `make snapshots` the screen snapshots, `make eval` the live prompt checks.
- Write tests where the logic carries risk; there's no coverage gate.
- `make lint` before pushing (`swift format lint --strict`, config in `.swift-format`).
- Pushing to `main` is allowed. **After pushing, run `gh run watch` and fix a red
  `main` before starting anything else.** The `gate` check sums up the run.

## Deploying the relay

`deploy/update.sh` (no sudo) tests, builds, swaps the binary and restarts it.
`make status` shows the deployed commit next to `main`; deploy after merging
relay changes so production doesn't drift.
